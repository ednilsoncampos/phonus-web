O contrato foi atualizado: docs/swagger-phonus-api-v1.yaml
para refletir a centralizacao das permissoes.

Veja um resumo
Centralização de Permissões — Phonus FC API

Problema: as regras de "quem pode fazer o quê" (ROOT/ADMIN/OPERADOR) estavam hardcoded em 39 pontos espalhados por 17 controllers do backend, e o front tinha que replicar essa mesma tabela manualmente em código próprio — sem nenhuma garantia de que as duas cópias ficassem sincronizadas.

O que mudou: o backend agora tem uma matriz única (papel × recurso) como fonte de verdade, e passou a expor essa matriz pela própria API.

Impacto direto para o front: GET /auth/me agora retorna um novo campo, além do papel:

{
  "id": "uuid",
  "nome": "João da Silva",
  "papel": "ADMIN",
  "permissoes": [
    "LANCAMENTOS_REGISTRAR",
    "FINANCEIRO_CONSULTAR",
    "CADASTROS_CONSULTAR",
    "CADASTROS_GERENCIAR",
    "ESTOQUE_GERENCIAR",
    "USUARIOS_GERENCIAR",
    "CONTA_PROPRIA"
  ]
}

Como o front deve usar: trocar qualquer if (papel === 'ROOT' || papel === 'ADMIN') espalhado pela UI por permissoes.includes('CADASTROS_GERENCIAR') (etc.). O backend continua sendo a autoridade real — sempre retorna 403 se a UI deixar passar algo indevido — mas agora front e back leem da mesma regra, então não há mais risco de a UI mostrar um botão que a API vai recusar (ou esconder algo que ela liberaria).
